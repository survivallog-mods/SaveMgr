# B 方案（注入式一键回档）验证报告（2026-10-31）

> 方法：Iced 反汇编（suite `tools/disasm_tool`）+ E8 调用方扫描，锚点全部来自 gamekb `2026-10-23_26157732`。
> 裁决：**静态证据链五环全通，注入环节零 Harmony、零私有格式**。唯一遗留：snap 独立可读性需一次实机实测。

## 证据链

### ① `AddHistoryEntry(fileName, name)` 是自足原语（RVA 0x28CFB30）

```
new HistoryChild → 存 FileName/Name → SaveOrigin=CurrentSaveOrigin
  → PeekGameSave(fileName)          ← 它自己去读 mod 刚复制的文件
  → AssignChildMetaFromGameSave     ← 从文件内容补 Day/MaxDay/角色/章节元数据
  → 追加 HistoryList（尾部）
  → SerializeObject → TemporaryFile.WritFile   ← 立即同步写 HistorySave.bytes
```

mod 只需：**先复制备份字节成 `Saves/Save_<新名>.bytes`，再调这一个方法**。顺序不能反（文件不就位则 meta 不补、列表不显示）。

### ② 列表显示三过滤全过（`Reducer_Web_MainUI.RebuildSaveList` 0x2BB9980）

| 过滤条件 | 注入条目 |
|---|---|
| `IsLegacySave(SaveOrigin)==false` | ✅ SaveOrigin 取注入时刻 CurrentSaveOrigin |
| `HasProgressMetaV2` | ✅ 反汇编实锤 `[child+0x48]=1`（AssignChildMetaFromGameSave 写入） |
| `IsSaveFilePresent(FileName)` | ✅ 文件是 mod 刚复制的 |

追加在 HistoryList 尾部 + 列表倒序遍历 = 注入条目出现在**列表顶部**，带正确天数/角色元数据。

### ③ 点击加载无门禁拦截

`Ac_MainUI_LoadSave` → `GameEntrance.EnterBattle(fileName, isLoading:true)` → `GetGameSave`(0x28DABA0) → `LoadWithBackupFallback`。疑点排除：
- `integrityBaseline` 不是校验门——`RebuildIntegrityBaseline` 在读档**之后**从数据重建（顾问指标）；
- `EnterNewerDataFileBlock` 只拦"更新版本游戏写的档"，同版本字节副本放行；跨版本恢复旧备份走迁移路径也放行。

### ④ mod 侧可调用性有先例

`BaseSingleton<GameSaveManager>.Instance` 直调，与 PlanPick/PreDisasterSpeed/WelcomeTip 同款（仓内 5 处先例）。公开实例方法，interop 直接调，注入不需要 Harmony。

### ⑤ 不污染"继续游戏"

`AddHistoryEntry` 不写 `LastPlayFileName`（反汇编确认）→ 注入档只能从"读档案"进。

## 边界条件（照单收下）

1. **注入档没有附带文件**：新档名无 `.snapN/.round/.ending`，原生"时光回溯"对它为空，第一次结算后才开始积累。备份时建议连带存 snap，注入时可选拉齐。
2. **重复注入=多入口**：每次恢复生成新时间戳档名，原档永不被动；玩家用原生删除按钮清理。`HistoryListMaxCount=1000`。
3. **时机约束**：限主菜单注入（historyData 已 Initialize、避开战斗中 HistorySave 并发写）；主线程调用（Ticker Update 模式现成）。
4. **文件名**：用游戏自己的 `GenerateNewSaveFileName()`（0x28D9CF0，公开），命名一致无碰撞。
5. **snap 独立可读性**：结构与主档同构（同一 `SaveGameFileCore` 序列化路径），静态置信度高；发版前需实机真注入实测（复制 snap→改新名→AddHistoryEntry→读档进游戏，规则 10）。
